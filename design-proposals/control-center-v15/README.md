# Yeisme v15：用户、Key 与完整请求

独立可操作原型，保留 v14、编辑室／电影工作台双主题与520px标准表单。不写真实配置文件、不签发真实密钥、不请求生产服务。

建议从 `index.html#team?org=studio&project=all` 进入：

1. 组织与访问 → 创建用户，填写组织内唯一登录名、团队、初始项目和角色。
2. 用户详情 → 为用户创建Key。完成后更新演示列表，仅在交付步骤显示新的DEMO代码。
3. 用户详情分别查看“可使用Key”和“创建的Key”，或切换身份检查授权范围。
4. 请求默认展示全部已接收样例，包含拒绝、限流、失败、取消、超时和结果未知；无产物请求仍有详情。
5. 从用户打开生产资源，组合生产者、Key、主体、团队、项目、服务、媒体、日期、固定版本、审阅和可用性筛选。
6. 项目详情查看负责团队、负责人、有效权限和Key；移交管理归属不改写历史生产者。

默认是制作团队组织管理员。组织页提供明确的“进入平台管理演示”，之后才能跨组织切换或查看未认证安全事件。

重置用户使现有会话失效，保留Key和历史；重置／轮换Key使旧值失效，保持稳定引用、递增版本，并保留旧请求归因。停用、撤销和轮换分开。最后管理员与项目负责人受到保护。

这是公开演示代码，不是安全认证实现。浏览器刷新会重建演示业务数据，新建用户和Key不视为真实持久化。演示身份引用与界面偏好可在当前浏览器保存；真实文件存储合同见 file-storage-contract.md。
