# Yeisme 控制中心：嵌套查看器的焦点回位 v1

## Why

交互路线第二轮 R5（`docs/interaction-roadmap.md`）。从任务详情里点“预览”打开全屏查看器，关闭后焦点落到页面 body，键盘用户要从头 Tab 才能回到详情；从任务行打开时焦点能正常回到行内按钮。2026-10-29 实测：用 Esc、关闭按钮或浏览器后退关闭，三种方式都落到 body；而且查看器还开着时，打开它的那个按钮就已经不在页面里了。

原因：申请预览句柄期间，`ResultViewer` 把预览按钮设为 disabled。`Button` 对带说明（`title`）的 disabled 按钮会套上提示用的可聚焦外壳，元素结构变了，React 就重新挂载按钮。查看器记下的打开者已经脱离页面，关闭时无处归还焦点。下载按钮在下载期间也有同样的问题，按 Enter 下载后焦点会丢。

## What Changes

- `ResultViewer` 的预览与下载按钮只在动作确实不可用时才 disabled。请求进行中保持可用，显示加载图标，设 `aria-busy`，并忽略重复点击，所以按钮不会被重新挂载。
- `Button` 的 `disabledReason` 注释写明：短暂不可用（请求进行中）的按钮应保持可用并忽略点击，切换 disabled 会重新挂载按钮并丢失焦点。
- 浏览器旅程的嵌套场景（任务详情 → 查看器 → Esc）断言焦点回到详情里的预览按钮。

## Owner Boundary

- 只改前端按钮状态与旅程断言，不改预览、下载的请求与授权逻辑。
