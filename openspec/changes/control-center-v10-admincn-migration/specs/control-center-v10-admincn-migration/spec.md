## ADDED Requirements

### Requirement: 行动优先总览

控制中心 MUST 在 1440×900 首屏同时展示待处理事项、三个核心服务摘要和当前作品上下文。

#### Scenario: 首屏发现阻塞

- **当** 用户进入一个有业务阻塞的范围
- **那么** 页面首先展示对象、项目、owner、观察时间、影响、原因/未知边界和明确下一步
- **并且** 统计、成本和历史趋势不能把这些内容推到首屏以下

### Requirement: 分层服务证据

服务详情 MUST 分别显示连接、授权、业务就绪、管理能力和观察证据五个维度。

#### Scenario: 连接正常但浏览器未授权

- **当** owner 端点可达但当前身份没有业务范围
- **那么** 连接显示正常、授权显示未授权、业务数据不显示假空列表
- **并且** 任何管理动作显示缺少合同或授权的原因

### Requirement: 运行上下文

项目、请求、领域任务、尝试、网关调用和资产引用MUST 通过非敏感稳定引用相互关联。

#### Scenario: 从镜头阻塞进入原请求

- **当** 用户从项目或镜头打开一个阻塞项
- **那么** 请求详情显示完整证据链，并提供返回原项目/镜头的定位
- **并且** 返回和刷新不能重复提交原操作或丢失草稿

### Requirement: 未知结果恢复

未知回包MUST 绑定原操作查询，不得自动创建替代操作。

#### Scenario: 查询原操作

- **当** 网络在提交后丢失回包
- **那么** UI 显示 `unknown` 并提供查询同一 `operation_ref` 的动作
- **并且** 未经明确授权不得自动重试、取消、退款或生成新任务

### Requirement: 移动与可访问状态

390px、键盘和减少动态效果MUST 保留查看、返回和安全恢复能力。

#### Scenario: 手机查看请求详情

- **当** 视口宽度为 390px
- **那么** 详情进入全屏、字段带标签、焦点和 Escape 行为可预测
- **并且** 不因隐藏列或压缩表格而丢失状态、来源和下一步
