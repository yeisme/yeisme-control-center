## 为什么

当前 `admincn-v7` 已统一外壳和六个入口，但 OpenDesign 控制中心原型已经暴露出下一阶段的产品问题：总览仍需要向下寻找真正的阻塞，服务状态容易被压缩成单一“在线”标签，项目、请求、资产之间缺少稳定的运行上下文。v10 以现有原型为输入，把这些问题固化为可执行的客户端规格，同时保留 owner 领域状态和只读聚合边界。

## 变更内容

- 新增行动优先的总览信息层级：异常/待决项、三个核心服务和当前作品在首屏形成可解释的处理路径。
- 将服务状态拆成连接、授权、业务就绪、管理能力和观察证据五个维度，禁止由单一颜色推导全链路可用。
- 为项目、请求、资产建立稳定的跨页运行上下文和返回定位；未知结果只能查询原操作，不能隐式重试。
- 把请求详情明确为 operation → domain task → attempt → gateway call 的证据链，并保留 stale、unknown、unauthorized、not_supported 等状态。
- 为手机、键盘、减少动态效果和错误恢复补充验收任务；OpenDesign 设计演示与正式客户端、真实服务验收继续分层。

## 能力

### 新增

- `control-center-v10-admincn-migration`：行动优先总览、服务证据分层、运行上下文和跨入口恢复合同。

### 修改

- `control-center-admincn-workspace`：补充五维服务状态、项目/请求/资产关联和 v10 交互状态。

## 影响

仅影响 `client/yeisme-control-center` 的 UI 规格、任务、文档、验证脚本和设计交接记录。不得新增 owner 领域写合同、浏览器服务密钥、远程 Shell、生产管理动作或真实内容采集。
