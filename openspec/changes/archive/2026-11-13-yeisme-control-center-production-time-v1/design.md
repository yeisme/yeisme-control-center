## 决策

1. **只用工具自己的计时。** 不建表，不做人工计时器，也不用创建或更新时间推算。没有计时的范围显示「没有计时」或「待接通」，不显示 0。
2. **两层合计，不相加。** 第一层是读取时的合计：只算已读到的任务页（每条泳道有上限），旁边写明覆盖数「x/y 带计时」。第二层是 Scaena 的整集合计，覆盖这一集全部派发记录，标「Scaena 汇总」。两者口径不同，所以分开显示。
3. **父子 run 不重复计。** 子 run 的时间段完全落在父 run 内时，算作父 run 的时间；只是指向上一次尝试的 run（Scaena 的重试）单独计时，并记一次重试。
4. **剧集归属只认 Scaena 的 `episode_ref`。** 其他工具的 `owner_episode_ref` 属于另一个命名空间，不参与匹配，这些任务进「未标注剧集」。
5. **实时走秒有边界。** 汇总时间取 `as_of` = max(页面当前时间, 计时任务最新的 `observed_at`)。前端从 `as_of` 起按「正在增长的 run 数 × 秒」累加，每秒最多刷新一次，标签页隐藏时暂停，回到页面时重新读取。停滞的 run 停在工具最后写入的值。
6. **编码不只靠颜色。** 执行和排队用实色，受阻用斜纹，等人用点状，未细分用灰色。图例始终写出类别名和数值；条形图是 `role="img"` 并带完整文字说明，另有表格视图。
7. **动效。** 条形只用透明度和 `scaleX` 出现一次（逐行错开 30ms）。减少动效时只做透明度，时长不超过 120ms。
8. **样本量。** 少于 30 个样本时只写「观察样本 N，仅供参考」，不给百分位。

## 风险

- Scaena 的计时是近似值：总时长取更新时间减创建时间，派发的执行时长等于总时长，受阻和等人时长没有记录。界面用「未细分」承接；Scaena 合计在 `splits_recorded` 为 false 时会写明这一点。
- 读取有分页上限：读取时的合计永远标「已读任务范围内」，完整合计要等 Scaena 汇总部署。
