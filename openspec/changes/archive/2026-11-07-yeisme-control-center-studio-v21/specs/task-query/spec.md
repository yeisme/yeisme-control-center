## ADDED Requirements

### Requirement: 查询语法
任务页 SHALL 支持 `键:值` 查询：

| 键 | 说明 |
|---|---|
| 状态 | 值可用中文别名，如「失败」「进行中」「等你确认」「未知」「完成」 |
| 工具 | |
| 集 | |
| 项目 | |
| 类型 | |
| 连接 | |
| 更新、创建 | 取值 `24h`、`7d`、`30d`、`今天`、`本周` 或 `a..b` |
| 有结果 | |
| 提示词 | |
| 排序 | |

- 以 `-` 开头表示排除。
- 引号里的词按短语匹配。
- 识别出的条件 MUST 写进与筛选栏相同的地址参数，并显示为筛选块。
- 无法识别的部分 MUST 按普通搜索词处理，MUST NOT 被丢弃。

#### Scenario: 组合查询
- **WHEN** 用户输入 `状态:失败 工具:eikona -雨`
- **THEN** 地址带 `state=failed` 和 `owner=eikona`，列表只剩 Eikona 中失败且标题不含「雨」的任务，筛选按钮显示「筛选，已选 2 项」

### Requirement: 匹配与排序
搜索 SHALL 先做 NFKC 规整，并忽略大小写和全半角差异。打分顺序：完全相同 > 前缀 > 词首 > 包含 > 子序列。有搜索词且没选排序时，结果 MUST 先按匹配分数、再按时间排序。

#### Scenario: 完整标题
- **WHEN** 用户输入某个任务的完整标题
- **THEN** 该任务排在第一行

### Requirement: 筛选计数与保存视图
每个筛选项 SHALL 显示计数，计算时排除该项自身的条件。用户 SHALL 能把当前查询存成视图：每个账号最多 20 个，并提供「需要回查」「等你确认」「今天更新」「有结果」「正在跑」五个预设。

#### Scenario: 保存视图
- **WHEN** 用户把当前查询存成「失败的图」并刷新页面
- **THEN** 「失败的图」仍在视图列表里，点开后还原同样的地址参数

### Requirement: 查询范围如实写明
查询 SHALL 只在已读取的批次上进行，并如实写明范围，例如「在已读取的 N 条里查询 · 每个连接的历史读了最近 8 页（还有更早的）」。
- 用户 SHALL 能选择「读取更早的历史」：每次多读 8 页，显示进度，可以取消。
- 游标过期时 MUST 提供「从头读取」。
- 控制中心 MUST NOT 声称查询覆盖了全部历史。

#### Scenario: 读取更早的历史
- **WHEN** 历史还有更早的页，用户点「读取更早的历史」
- **THEN** 新读到的行合并进列表，范围说明里的页数随之增加；切换工作范围后，这些行被清除
