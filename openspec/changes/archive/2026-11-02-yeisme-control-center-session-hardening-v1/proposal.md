# Yeisme 控制中心：会话与账号管理加固 v1

## Why

对控制中心做整文件审阅，复现了十处问题，其中两处是“命令不起作用”：

- `personal-config user revoke` 只改了配置文件，运行中的服务只认内存里的账号列表，也不看密钥摘要文件，所以吊销后旧会话仍是 200、被吊销的密钥仍能登录，直到重启；文档却写着轮换、吊销无需重启。
- `POST /admin/personal-users/{用户名}/revoke` 永远走不到：前缀下所有 POST 先被“创建账号”分支接走，空请求体得 400、账号仍启用，创建形状的请求体发到吊销地址反而建出一个账号。

另有：吊销没存进文件就被之后的写入或重读悄悄撤销；个人会话不管多活跃都在登录 30 分钟后结束（最后活动时间写在副本上）；坏的客户端输入被当成 503，而发布读回遇到 5xx 会回滚；`/actions` 创建账号丢掉访问密钥；另一个标签页换人登录后旧标签页毫无察觉；退出登录失败被静默吞掉；`/usage` 按范围自带的 `project` 标签筛，个人配置的范围永远看不到用量；后台任务的未处理拒绝会让 Bun 进程退出。

## What Changes

- 服务端处理每个请求前比对配置文件（一次 `stat`），变了就只重读 `personal.users`：新增、吊销、启用、轮换对下一个请求生效，已吊销账号的会话立即结束；`personal-config user` 的输出带 `restart_required: false`。
- 网页吊销记为“待存”，随之后每次写文件和每次重读一起应用，文件记下后才以文件为准；存不进去不会丢吊销。
- 账号路由完整匹配：集合路径只接 GET 与 POST（创建），吊销路径只接 POST 且不读请求体，其余 404/405。
- 会话新增 `touch`：最后请求时间每分钟最多写一次，空闲 30 分钟的语义不变；登录限流只计凭据被拒的次数，登录正在核验时到达的另一个登录得到 429 `login_busy`，界面分别说明。
- 路径参数的非法转义、非对象 JSON 请求体是 400，并发同名创建是 409。
- `admin.user.create` 在动作目录里标为不可用（中文原因指向 `personal-config … add --key-file`），预览与确认都返回 422 `action_unavailable`。
- 新会话的 epoch 高于之前任何会话；前端收到 403 `csrf_denied` 时重读 `/session` 并提示；退出登录要等服务端确认，失败时保持登录并提示重试。
- `/usage` 按运行的范围过滤（用量行经 owner 与来源引用找到运行）。
- 后台状态轮询不再把读账本失败变成未处理拒绝；进程装上 `unhandledRejection` 处理器，只记错误码、不退出。

- 安全复查后追加：网页与 `personal-config` 共用配置文件独占锁，命令行不用旧副本覆盖网页刚存的吊销；每个账号的会话数与登录次数有上限、闲置会话先清，一个有效账号拖不住别人；不存在的用户名与密钥错误同样处理；读不到账号文件时记日志、命令行只以文件所有者身份写；账号是否启用只有一条规则；被拒的 CSRF 令牌不再让页面循环重读。

## Impact

- 不改配置文件格式、数据库表和迁移；会话 epoch 的数值从 1 变成时间量级，`verify-server-boot` 与 `verify-contract-integration` 里写死的 `epoch === 1/2` 改成相对断言。
- 吊销没能存进文件时，重启会丢掉“待存”的吊销（503 已经告诉了调用方），文档要求在服务器上用 `personal-config user revoke` 补上。
- 不涉及 OIDC 模式的问题、cookie `__Host-` 前缀、审计里的用户名处理。
