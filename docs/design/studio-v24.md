# Yeisme Studio v24 · 项目页美化

- 状态：已发布到内网 2026-11-11（`openspec/changes/yeisme-control-center-studio-v24/`）；源码未提交
- 日期：2026-11-11
- 接续：[v23](studio-v23.md)
- 适用：`client/yeisme-control-center`

## 0. 一句话

v23 把项目放到了中心，v24 让它看起来像一个项目：列表有封面，主页头部更紧凑，没有缩略图的成果也能分辨，连接按工具分组。只改展示，不改服务端、迁移和依赖。

## 1. 原则

1. **只显示读到的东西。** 封面只用控制中心已存的成果行，不为一页卡片访问工具；读取截断时 `total` 不准，所以列表不放计数。
2. **同一件事只说一次。** 「项目」不在头部写两次；一组连接状态一致时，「还没读过」只在组头写一次。
3. **ID 不是标签。** 原始范围 ID 只放在 `title` 提示和可复制的项目引用里。
4. **少说「owner」。** 显眼的地方都改成「工具」。

与方案的两处偏差：

- 方案里副标题写「项目 · 组织名」，但会话里没有组织名，所以写「共享项目」。
- 方案里的文案是「未接工具」，实际用「暂无连接」：新项目在第一次观察之前也会显示这个状态，这时它已经接了工具。

## 3. 连接分组规则

- 按工具第一次关联的顺序分组。
- 组内状态一致：组头显示这个状态，行内不写。
- 组内状态不一致：组头显示第一个问题状态（没有问题状态时是「还没读过」），每一行都写自己的状态，避免没写状态的那一行被当成正常。

## 6. 发布

2026-11-11 只发布控制中心。工作区是多条工作流共用的，所以这次发布同时带上了其他工作流已完成的两条迁移（线上 15 → 17）：

- `project_collection_bindings` 新表（剧集来源绑定）；
- `sessions.remembered` 列（「记住此设备」，变更 `yeisme-control-center-session-keepalive-cache-v1`）。

两条都只新增表或列。切换前在线上库副本上做了升级演练：既有表行数不变，`integrity_check` 为 ok，没有外键违规；用旧版本启动升级后的副本也正常，所以回滚只需恢复 unit。切换前另存了 0600 恢复点。
